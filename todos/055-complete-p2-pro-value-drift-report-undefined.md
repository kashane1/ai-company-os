# Problem Statement

`pro-value-audit` is the only sibling that mentions a "drift report" as a refusal output but never defines its structure. Every other contract surface in the recon-family (per-prompt template, output skeleton, coverage matrix columns, readiness flags) is field-locked. The drift report is the one ad-hoc surface.

When the rubric's "Free/Pro rule (verbatim)" section drifts from `MONETIZATION.md`, the canonical body and adapter both say "refuse with explicit drift report" — but a reader receiving the refusal has no idea what should be in that report.

## Findings

- **spec-flow-analyzer:** "'Drift report' is referenced four times across canonical+adapter (`pro-value-audit/skill.md:95,214,223`; adapter `:22,52`) but never structurally defined. No sections, no fields, no template. Adapter `:22` says 'refuse with explicit report'; canonical `:223` says 'refuse with explicit drift report; operator reconciles before audit re-runs.' Operator gets an undefined deliverable."

## Proposed Solutions

### Option 1: Define the drift-report schema explicitly

Add a section to `skills/canonical/pro-value-audit/skill.md` titled "## Drift report format" with binding fields:

```
### Drift Report

**Generated by:** pro-value-audit refusing to proceed
**Generated at:** YYYY-MM-DD HH:MM
**Rubric file:** docs/products/<product-id>/pro-value-rule.md
**MONETIZATION file:** docs/products/<product-id>/MONETIZATION.md

#### Rubric verbatim block (Free/Pro rule section)
<copy of the rubric's Free/Pro rule section>

#### MONETIZATION verbatim block
<copy of MONETIZATION.md's Free/Pro rule section>

#### Diff (line-level)
<unified diff of the two blocks>

#### Proposed reconciliation
<one-paragraph suggestion of which side likely needs updating>
```

Pros: gives operator an actionable artifact; locks the contract; reproducible across audits
Cons: requires the audit to actually produce a diff
Effort: Small
Risk: Low

### Option 2: Downgrade language

Replace "drift report" with "explicit refusal message naming both files and quoting the disagreement (with line numbers from each file)." Strip the word "report" — it's not actually a report deliverable, just a refusal message.

Pros: simpler; honest about what's actually produced
Cons: weaker artifact; operator has to do the diff manually
Effort: Trivial
Risk: Low

## Recommended Action

**Option 1.** The drift case is rare but high-stakes (Pro audits depending on out-of-sync source-of-truth). An operator hitting this should get a real artifact, not a vague refusal. The added skill body is ~15 lines.
