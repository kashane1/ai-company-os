# Example artifacts

These are real, schema-faithful artifacts produced by the end-to-end demo.
They are generated by constructing the actual domain schema objects
(`packages/schemas/`) and serializing them, so they cannot drift from the
production schema — if a schema changes and these are stale, the demo and
its test fail.

| File | Schema | What it shows |
|---|---|---|
| `sample-task-run.json` | `packages/schemas/task_run.py` | The full per-run audit artifact: typed execution record, pre/post git state, validation checks, classification, linked approval. This is the "I can replay exactly what an agent did and why" claim, concretely. |
| `sample-approval.json` | `packages/schemas/approval.py` | A resolved human-in-the-loop approval gate for an irreversible action (`merge_pr`), with decider and decision notes. |
| `sample-postmortem.json` | `packages/schemas/postmortem.py` | The failure-path audit record emitted when a run fails — every string field is redacted at the schema boundary. |

## Regenerate

```bash
make demo          # or: ./scripts/demo.sh
```

This prints a narrated transcript of the control loop and rewrites the
files above. It needs no external services.
