# Example artifacts

These are **synthetic fixtures**, constructed by
[the demo](../../scripts/demo/run_demo.py) with the real domain schema classes.
They illustrate record structure. The identities, timestamps, commands, git
changes, validation results, and approval decisions are invented sample data.
The demo does not execute a worker or obtain a human decision.

| File | Schema | What it illustrates |
|---|---|---|
| [sample-task-run.json](sample-task-run.json) | [TaskRun](../../packages/schemas/task_run.py) | Execution fields, git snapshots, validation results, and an approval link |
| [sample-approval.json](sample-approval.json) | [ApprovalRecord](../../packages/schemas/approval.py) | The shape of an approved record for `merge_pr`, including example decision metadata |
| [sample-postmortem.json](sample-postmortem.json) | [PostMortem](../../packages/schemas/postmortem.py) | A failure record; this sample corresponds to the separate failure fixture |

Task-run and approval samples describe a successful fixture; the postmortem
describes the alternative failure case. Referenced runtime paths such as
`diff.patch` are illustrative and are not generated by this demo. Loading a
record back into a schema is a serialization check, not replay of an agent run.

## Regenerate and validate

From the repository root, with Python 3.10+ and Bash:

```bash
./scripts/evaluator_check.sh
```

This rewrites the three JSON files and checks them. To only regenerate and
print the illustration, use `./scripts/demo.sh` or `make demo`.
No external services or Python package installation are required.

For tests of actual approval enforcement, follow the
[evaluator walkthrough](../EVALUATOR-WALKTHROUGH.md).
